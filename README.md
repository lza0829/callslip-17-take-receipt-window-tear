# 叫号条（Callslip）

银行网点柜面叫号：取号入队 → 叫号推进 → 过号回收/重叫 → 当日队列封口。

- 前端 http://127.0.0.1:6400
- API http://127.0.0.1:11400
- `docker compose up -d --build`

## 假发号收口（架构一：四表同命运，全局唯一）

成功灯不是文案，是可重放的证据。**发号亮绿 ⇔ 开放窗计数 ∪ 号段游标 ∪ 等候队列表 ∪
成功流水行 四者同命运成立**。任一侧对不上，整笔发号回滚到发号前快照并回退成功流水行；
禁止只改成功单号文案，禁止旁路改等候计数冒充已发号。

- 开放窗口唯一谓词：`windows.open=1`，定义在 `app/services/core.py` 的
  `OPEN_WINDOW_PREDICATE` / `open_window_count()` / `open_window_names()`；
  发号写入侧、等候墙、总览、窗口开闭页、发号回执全部经同一个 `issue_gate()`。
- 发号事务：`take_ticket` 以 `BEGIN IMMEDIATE` 取写锁后重读游标，在同一事务内完成
  「闸判定 → 落号 → 推游标 → 写成功流水（带开放窗名快照）→ **四表重放自检**」。
  自检 `verify_issue_replay()` 不通过即抛错，整笔（含成功流水行）回滚到发号前快照。
  收档（`set_open(..., False)`）同样先取写锁，与发号串行，杜绝并发双破硬闸。
- 对账 `issue_integrity()`：枚举当日每笔成功，校验号牌行存在且号/日/种类一致、
  游标恰进一格、成功行带开放窗证据、种类游标等于最大成功 `seq_after`。
  有缺口则 `issue_gate()["可发号"]=false`、`原因="发号证据缺口未清"`——
  **缺口未清前，等候墙、总览等候桶、窗口页一律不亮已发号，发号口也拒收新成功灯**。
- 旧版「成功面板」旁路已删除：原先它在提交后另开事务写 `surface_*` 设置、删号牌行、
  回退游标、把成功流水改成「成功注记」，造成「单号亮绿 / 开放窗为零 / 墙空 / 流水成功」。
  现由 `app/services/reconcile.py` 收口，且启动时（`seed_if_empty`）幂等执行。
- 同刷接口：`GET /api/发号闸`、`/api/等候墙`、`/api/总览`、`/api/窗口页` 均带
  `发号闸`（`可发号`/`开放窗口`/`完整`/`缺口`）；`POST /api/取号` 成功回执带 `回执`
  （含 `开放窗口名`），失败返回 400 并落 `发号流水`（`GET /api/发号流水`）。
- 对账/收口接口：`GET /api/发号对账` 只读体检；`POST /api/发号对账/修复` 幂等收口
  （冲正「成功注记」、回退无号牌行的成功、作废缺开放窗证据的号牌、按成功流水夹正游标、
  清除伪造面板键）。
- 测试：`cd backend && .venv/bin/python -m unittest discover -s tests -v`
  覆盖零窗拒发、失败不入队、游标不动、并发发号不跳号、并发收档抢最后窗口、
  半截失败回滚；以及夜班假发号夹具 `tests/test_fake_issue_tear.py`：
  单号绿开放窗为零、游标加事件无行、墙空流水成功、收档对撞半截、六读路径与审计同刷。
